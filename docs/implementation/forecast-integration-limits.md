The Factory SDK runner and real persisted tools were tested through deterministic SDK transport; no live Factory request was run. The SDK package is not installed in this backend environment.

## Product and data limits

- Slack, Asana, Monday, and release feeds use connector-shaped synthetic envelopes and a deterministic bounded interpreter. OAuth, webhooks, authenticated live acquisition, and open-ended language extraction remain subsequent integration. Unknown semantics are context-only.
- Native document and signal changes now enter canonical evidence automatically. Exact passages and verified citation references are preserved; summaries and legacy multipliers are not treated as observed quantities. The explicit forecast demo shares one directory across frontend/native APIs and Droid, while the separately retained native charge ledger discloses unavailable fixture-person attribution.
- Trusted integrations can submit exact observed target outcomes through `/api/forecast-outcomes`. Completeness, source attestation, dimensions, maturity, synthetic status and server receipt gates are validated. Live source acquisition/authentication and automatic derivation from ordinary incomplete ledger imports remain external; an attestation is not independent source verification.
- Structured Droid tasks enforce action/run/scope constraints. The tested native explanations fit the SDK result cap while retaining citations and temporal effects. Arbitrarily larger receipts may still explicitly truncate at 60,000 characters. Pending scenarios return durable identities/status; standalone agent polling is not a separate SDK tool, while the dashboard and REST endpoints support retrieval.
- Default repository records do not establish daily source completeness, exposure, or supported usage pricing. Explicit native person identities are retained; unknown identities remain shared. Recorded charges are visible, but unsupported future and quarter totals stay incomplete. Archived source-state revisions preserve subsequent changes; historical states before reliable capture cannot be reconstructed by inventing old mappings.
- The Northstar served demo keeps the finance ledger on the same observed days as native current actuals. The legacy ledger rounds each imported record to cents; native usage-derived estimates retain precision. Those distinct numerical representations are explicit.
- All billing days are UTC. No local-day reassignment is made from daily aggregates. A manual run excludes today's unobserved remainder and can have a partial first planning week.
- Shared allowances, supported tiers, and fixed terms use complete-pool pricing. Annual commitments, complex credit lifecycle, FX/tax, and unsupported obligations do not become fabricated totals. Quarter continuation can affect earlier monetary allocation under nonlinear terms; the output records that dependence.
- Low/base/high ranges describe evaluated branch means. Their envelope is neither exhaustive nor a confidence interval. Historical 80%/95% intervals require compatible, mature, nonoverlapping errors and can remain unavailable, especially for long cumulative targets. Pointwise bands provide no simultaneous trajectory guarantee.
- Historical replay and the demo are synthetic mechanism evidence. They cannot demonstrate enterprise predictive accuracy, real-world coverage, savings, or a production-winning model. The frozen replacement policy requires genuine data and elapsed prospective comparisons; fixtures cannot pass it.
- Local SQLite persistence, leasing, and restart recovery are implemented for this deployment. This is not a distributed service or production identity system; the existing demo role headers are not authentication. Allocations remain internal planning records with the existing finance approval controls.

The bulk data loader holds the forecast maintenance lock across loading and atomically clears canonical forecast/archive state on an explicit reset. Failed loads restore the previous database. Archive v2 stores changed rows and tombstones instead of full repeated ledgers; existing v1 captures stay intact. A reproducible 60-import × 20-row benchmark reduced stored JSON payload from **71,133,675 bytes to 787,048 bytes (90.4×)**. This measures payload bytes, not total SQLite file size or production throughput. Current-state capture still scans material, and separate-database synchronization is a snapshot transfer. The 331,730-row generated history with two-second live imports has not been validated at that cadence.
