Commercial transformation is a complete per-global-path, per-reset-period shared-pool estimate. Exact configuration/meter/unit/pool catalog lookup includes quantity denominator, contract currency, version, known-at and effective interval. Missing or ambiguous rules, incompatible meters, incomplete prefix/remainder coverage, skipped/overlapping reset periods, duplicate meters and currencies without an explicit FX transform fail the monetary view independently. A single native `ScenarioBundle` is adapted without separately coupling draws; original path IDs and weights survive. Existing complete-pool tariff arithmetic runs before proportional allocation of signed prefix/future/fixed components. Exact Decimal allocation conserves each period/path, including negative volume repricing increments and hostile ambient precision. Results retain contract/allocation/rate versions and immutable material input identity.

The pure chronological reducer shares quota and concurrency across entities in one declared pool/unit. Admission reserves atomically; acknowledged execution end/cancellation frees concurrency without erasing settlement liability. Settlement releases reservation once. Hard bounded attempts reject charges above their bound; estimated reservations permit visible overshoot. Resets/reconfigurations retain open liability, and estimated reservations do not become hard bounds merely because policy mode changes. Opening attempts are explicit. Delivered starts bypass another admission and invalidate hard assurance. Internal budget events leave physical state unchanged. Ordered inputs and opening state bind `ControlResult.input_id`. `ControlAdmission` is a narrow scenario callback, with per-path fresh ledgers through `.for_path`, explicit lifecycle `.apply`, and caller-supplied Decimal liability marks.

## Self-review and limits

- These are supplied/synthetic conditional contract estimates, not posted charges, invoice/cash inference, provider dispatch or enforcement. No real rates are invented. Hard assurance is conditional on caller-supplied true bounded liability and complete opening state; it is never a provider guarantee.
- Catalog supports existing linear/graduated/volume complete-period tariff primitives. An intra-period price change requires a temporal tariff adapter and is unavailable here; announced future full-period tariffs can be eligible if origin-known. Multiple compatible meters may consume one pool tariff; different unit tariffs, request-context thresholds, FX, tax, credits, seats and commitments need explicit additional adapters.
- Exact finite Decimal division is required for denominator conversion; a repeating result is unavailable instead of rounded. Float model cells are explicitly valued via Decimal(str(cell)); exact money arithmetic does not make modeled token quantities measured facts. Original probability weights remain float when the source bundle uses float weights; no exact expected-value claim is added.
- Full-period completeness and disjoint known/late economic coverage require explicit caller evidence. The bundle adapter verifies all native path/pool/date coverage and meter manifests; it cannot certify that an upstream source omitted an economic meter. Low-level `price_usage_paths` prices the declared period set; use `price_bundle` for complete horizon coverage validation.
- One pool/unit per control reducer; shared entity reservations are atomic in that scope. This is a passive sequential scenario state machine, not a distributed lock or simultaneous multi-scope provider controller. `ControlAdmission` requires explicit lifecycle events; unacknowledged starts intentionally retain capacity/liability. The physical generator currently calls admission on proposed new roots; existing continuation lifecycle wiring remains caller-owned, and delivered mode bypasses admission in the state module.
- No empirical monetary accuracy, cap causal effect, joint tail calibration, or real provider financial reconciliation is established by synthetic mechanism tests.

## Independent review fix round 1

Addressed all four findings in `task-5-review.md`, limited to owned modules/tests. The earlier reported semantics are superseded where noted below.

1. **Terminal settlement invariants.** `simulate_controls` requires acknowledged execution end or cancellation before settlement. A reservation can be cancelled before start and settled, but cannot subsequently start. `Attempt` validates opening lifecycle flags and rejects settled/nonterminal opening state, including settled live starts. Existing duplicate-settlement and estimate-policy-transition fixtures now include valid cancellation acknowledgement before settlement, so they test their intended behavior through a valid lifecycle.
2. **Trajectory breach and qualification retention.** `ControlState.peak_overshoot` and `hard_assurance_lost` carry forward across every event and resumed chunk. State construction captures opening deficits and any estimate-mode/unbounded/bypass qualification. Reset refreshes current debit without erasing breach history. `ControlResult.overshoot` now reports peak retained trajectory deficit; new `final_deficit` reports ending deficit. Hard assurance is for the retained trajectory and cannot be regained by switching from estimate to hard mode. No final-balance-only assurance remains.
3. **Empty pricing interval quantities.** `_price_one` rejects nonzero known/late prefix in `[period_start,period_start)` and nonzero future in `[period_end,period_end)`. Because `price_bundle` shares this commercial transform, both entry points enforce it. Explicit zero atoms remain valid. The exact November future-period reproduction (100 alleged prefix + 30 actual modeled future units) returns unavailable; the zero-prefix control returns 30.
4. **Resumable audit cursor for budget events.** Budget-only events persist `last_at/event_ids` while leaving physical policy, attempts, debit and available balance unchanged. Opening continuation and `ControlAdmission.apply` now reject earlier physical/budget events and duplicate IDs following budget-only chunks. Existing physical invariance assertions compare physical fields rather than entire audit-bearing state identity.
