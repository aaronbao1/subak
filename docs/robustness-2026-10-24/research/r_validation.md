## Current evidence and priorities

`src/forecasting/evaluation.py` already provides unusually good foundations: immutable label revisions, availability plus maturity, latest-revision disputes suppressing stale mature truth, target-identity checks, half-open splits, lineage/derivative grouping, locked D-only selection, all-opportunity denominators, separate company comparisons, pending warning bounds, donor accounting exposure and capability-specific promotion gates. `uncertainty.py` rejects overlapping calibration periods and refuses unsupported conformal ranks. These mechanisms should be reused. Existing relevant verification was executed: `PYTHONPATH=src python3 -m pytest -q tests/test_evaluation.py` → **33 passed**. This is software evidence, not model performance evidence.

Four small common changes have highest value:

1. **Replay the serving bridge.** `evaluate_rolling` lines 435–451 starts its history suffix at origin−1. I executed a constant 50-day series with every observation delivered three days after service. Despite 38 mature contiguous history days, `trailing_mean` becomes unavailable: “no mature contiguous history through origin.” Serving already allows explicit delayed `history_end`; evaluation should execute the same registered bridge, predicting lag plus future target and slicing the exact target. Keep missing late-incurred amounts unknown. Otherwise delayed billing cannot be measured fairly, and a model-only benchmark misses an important operating condition.
2. **Freeze a content-addressed full procedure and opportunity manifest.** `LockedSelection` freezes candidate name, while `evaluate_rolling(configs=...)` and calibrator `procedure_id` are externally supplied. Bind model checkpoint revision, feature/preprocessing specification, context length, seed/refit policy, projection/clipping, pricing/aggregation, fallback and calibrator into one digest. Bind that digest to fixed target/origin/population manifests. A changed digest requires new calibration/final evaluation. Keep configuration search trials distinct from folds: my probe recorded a losses 100 and 0, b loss 5; `freeze()` selected a's best trial. This is valid only if each record means a separate registered complete procedure, not a fold/seed. Enforce one aggregate D loss per procedure, or explicit trial identity plus aggregation.
3. **Make origin state part of the manifest.** `cohorts` and `companies` are entity dictionaries fixed across all origins (392–394,486). The same entity can be cold, warm, then recently migrated. Bind cohort, ownership and release-relative state by opportunity, using only as-of evidence. The separate `validate_population` is sound, but nothing in `evaluate_rolling` invokes it or filters the pooled panel; unseen-company evaluation must exclude all held-out lineage derivatives from fitting while clearly allowing legitimately observed warm history in a different experiment.
4. **Separate delivered accuracy from all-issued conditional accuracy.** `summarize_opportunities` scores every prediction with mature truth, even late/stale rows. A probe with one late prediction returned availability 0 and point.n 1. This is not necessarily wrong, but the report must explicitly name it all-issued conditional accuracy and add on-time accuracy. Selection must consider delivery/fallback on common opportunities. Continue retaining all pending/high-cost failures and all available support counts.

## Basic real-trace protocol usable now

The benchmark workers own data/runtime implementation; this protocol was sent to both. Use a genuinely public token-usage/serving trace, retaining original timestamp range, fields, dataset/license source, byte SHA, filters and coverage. Aggregate equal native-time bins. Drop partial edge bins or mark them incomplete; internal missing bins are unknown unless the source establishes observation coverage. Preserve input/output counts and total-token conservation. Do not invent team identities, daily dates, invoices, budgets or company context. Any monetary transformation is a separately labeled hypothetical repricing, not reported spend.

Freeze horizons **1 and 4 bins**, context up to **64 bins**, and common origin IDs before final inference. If sufficient history exists, use earlier data for D, reserve any actual uncertainty calibration C, then untouched final 20% time for F. For a zero-shot feasibility comparison without tuning, fixed preregistered procedures may simply use a held-out final segment; do not imply D/C occurred. Prefer nonoverlapping final targets for basic support and report the actual number of independent time blocks. Fewer than five nonoverlapping blocks is feasibility/descriptive evidence only. Long synthetic date relabeling must never turn a minute trace into a monthly forecast test.

Compare pinned pretrained foundation model with last observation and trailing mean (fixed 16-bin window). Add seasonal naive only if an honest repeated period is present; add zero as a transparent diagnostic for sparse series. Every candidate receives identical available prefix and target. A framework may require more context; record unavailable opportunities instead of quietly selecting easier targets. Record dependency/checkpoint hashes, loaded bytes, seed, device, cold model-load time, warmed inference latency, failure reasons and all fit attempts. Native foundation median forecasts remain median/point; sums of marginal medians are labeled a summed point heuristic rather than cumulative mean. Do not sum marginal quantiles into cumulative intervals. Retain all candidate results, not only the winner.

Primary scores are cumulative target MAE, RMSE, signed bias and WAPE with undefined denominators preserved. Include per-origin losses, availability, worst-window absolute loss, fixed predeclared zero/high-load/burst slices where measurable, and source/maturity exclusions. Report point-statistic differences explicitly. Compare matched paired loss descriptively; many requests or overlapping origins are not many companies. Foundation pretraining contamination of a public trace may be unknown and must remain a limitation. These results establish runtime feasibility and narrowly measured token-load predictability. They cannot establish enterprise transfer, monthly team-spend accuracy, calibrated breach probability, workflow savings or allocation safety.
