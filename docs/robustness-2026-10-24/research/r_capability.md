## Small common mechanisms

**1. One immutable catalog snapshot, with distinct facts.** Freeze release/spec identity, serving configuration, capability evidence/anchor, policy, and alias resolution as separate revision types under the same available-at/effective-time envelope. Configuration includes effort, scaffold/tools, context regime, platform, and region. Capability evidence carries task/rubric versions, coverage and uncertainty. An entry with unknown quality can still support a metered-usage forecast. A new quality measurement must not reclassify the old reviewed forecast. Equivalent aliases deduplicate a catalog capability denominator while their actual call IDs remain distinct.

Use requested, actual served, and billed identity separately. Internal provider fallback can yield one physical call; an explicit failed call followed by an escalation can yield two. Never generate billing from a routing-decision count. Pricing research agrees the tariff key must add seller/channel, region, service tier and meter schema/unit to billed identity. A matching name alone is insufficient. Meter/tokenizer compatibility is required for frozen repricing; same-task migration regenerates marks and belongs to the joint scenario kernel.

**2. One feasible action set and pathwise transition kernel.** Select alternatives using task requirements, context/output limits, tools/modalities, access, region and policy at that event time. Deterministic default rules execute exactly; discretionary behavior may use a pooled stochastic choice model with switching inertia and an outside option. Price/quality does not imply instant optimal switching. Maintain root/attempt genealogy and route reason. Adaptive routers require evolving policy state and explicitly budgeted learning; a frozen-policy replay must not quietly train on future outcomes.

Sample quality/configuration uncertainty once per catalog unit and global path and reuse it for everyone. Conditional task outcomes may vary; shared epistemic uncertainty must not diversify away as headcount rises. Preserve task difficulty across escalations so the same hard task can defeat every model. Couple selected configuration to steps, retries, native token marks, success and cost. A benchmark score cannot serve as a direct token multiplier.

**3. Typed distribution views computed inside paths.** Available catalog, intended choice, physical calls, token meters, gross charges and successful roots are different populations. Every share carries numerator/denominator definition, native unit, scope, task profile, anchor version and zero-exposure probability. Unknown/mixed profiles remain explicit mass. Two nonexclusive attainment statements cannot form an exclusive pie chart. Crossing profiles require task-specific comparisons rather than a total intelligence order. Credits belong beside gross-charge shares; a signed net contribution is not a probability share.

The mechanism must calculate a ratio within each positive-exposure path before averaging. For equal-weight paths with (tier,total)=(1,1),(0,9), expected share is .5, whereas ratio of expected totals is .1. A no-activity path has undefined share, not zero quality. Input, output, cache and reasoning meters cannot silently be pooled across incompatible tokenizer/count bases. When evidence is aggregate-only, keep a usable aggregate forecast and omit unsupported mix details rather than discard all forecasts.

Regression: a later cheap candidate has zero share before known access; migration can change token marks; a hypothetical unannounced release is scenario-only and never enters baseline history.
