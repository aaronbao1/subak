## Four changes that cover the cases together

1. **Add a passive execution-evidence ledger beside daily financial rows.** Keep root goal, logical operation, physical attempt, unique meter event, and conversation identities distinct. Typed edges include child, retry, fallback, resume, shared-work, and join. A physical meter event has one authoritative charge role; wrapper totals are reconciliation evidence, never extra additive charges. Distinguish initiator, executor, payer, beneficiary, and time-effective cost-center allocation. Unknown linkage preserves measured daily totals in an unlinked bucket; it does not discard usage or manufacture a root. Use the observation specialist's source/component/epoch/interval meter identity and the controls specialist's chronology, avoiding duplicate schemas.

2. **Replay an immutable as-of prefix and partition its future.** Each state event carries occurrence and availability times, policy/workflow versions and stable ordering. A known cancellation request differs from an acknowledged terminal stop; waiting is not running; unknown logging is not success. Known accrued charges, uncertain incurred bills, future work from active roots, and future newly arriving roots are disjoint components. Old-root work consumes its actual service interval, not its root-start date. Duplicate deliveries do not create attempts; distinct provider attempts are retained even when prompts/logical operation IDs match. Chronological replay must reject cycles, impossible state transitions and conflicting identities while accepting out-of-order delivery once its actual availability allows it.

3. **Start with bounded conditional paths and empirical task-family replay.** A useful implementable baseline bootstraps whole observed root families by task/workflow and current prefix state; a supplied finite transition kernel can simulate attempts, routes, durations, forks/joins and post-transform context. Sample shared root difficulty/outage state once per path so retry depth, escalation, output size and verifier cost remain dependent. Do not force a branching-tree formula onto shared-worker DAGs. Include planner, summary, selector/verifier and tool events. Workload policy is an input; the forecast does not enforce it. Stop/fallback limits bound simulation and yield explicit unfinished mass rather than natural-success labels. Unknown transition rates need disclosed conditional scenarios and empirical support gates, while daily forecasting continues from complete aggregate evidence.

4. **Evaluate exact targets and intact families.** Separate remaining-period spend from eventual root lifetime cost, and actual served-policy spend from uncapped desired work. Hold out complete restart/fork/template families for unseen-task experiments. Operational continuation tests may lawfully condition on the observed prefix, but future stop causes, final token counts and late route/cache metadata cannot enter it. Compare daily-only, daily-plus-activity and active-prefix-plus-new-root approaches on the same eligible observations and report active-root coverage. This validates whether tracing adds value instead of assuming graph complexity improves forecasts.

## Why the compound cases matter

Retry after a client timeout can coexist with a billed original request; provider fallback can invalidate a cache and force history replay; parallel candidates can all be billed before one is chosen. Compaction adds its own call and may change subsequent repair frequency. A departed employee's old root can continue under a service key after their team mapping changes. These are not independent scalar adjustments: multiplying average calls by average tokens misses their shared root state and can double count descendants as adoption. The smallest common defense is an identified event graph, typed state history, disjoint temporal accounting and pathwise pricing/conservation.

Shared-worker reconvergence needs special care. A verifier serving two branches is one physical bill, with attributable weights summing to one if multiple cost centers benefit. A join can wait on all branches, race for the first acceptable result, or wait for a quorum; the stop rule changes elapsed time and residual in-flight bills. No generic completion state implies that all branches ceased accruing simultaneously. Cached token counters remain the observation/pricing layer's responsibility; workflow state only records route/prefix/compaction/cache eligibility evidence, never a universal cache discount.
