# Minimal architecture: one evidence-bound forecast procedure

Both original transcripts and the master plan were read in full. Internal transcript references below use line 6 plus distinctive phrases because nearly the whole discussion occupies that line. Current implementation was inspected; no product code was changed and no new statistical mechanism was executed by this worker. The restart architecture/contracts are proposed interfaces, not current capabilities.

## Decision and scope

Implement one procedure with five invariant boundaries: **as-of evidence → declared observation/process mode → aligned numerical bundle → financial transformation → qualified output**. Six work packages below implement those boundaries and their benchmark. This compresses the taxonomy without pretending that a single latent variable called “spend” can represent everything.

The master plan §§1–3 establishes team-level finance, distinct usage/charges/credits, internal allocations and contextual evidence; §§7 and 10 require a limited genuine benchmark and honest uncertainty. The internal discussion explicitly debates fragmented bills versus projections, new models, teams versus individuals, and coarse versus per-experiment prediction. Mentor transcript lines 17–27 distinguishes delayed incurred obligations from future forecasts; lines 40–53 challenges representative data and simple trailing averages; lines 121–148 challenges new models, adoption and unknown shocks. A unified implementation should preserve those distinctions while still forecasting available aggregate history.

## Existing foundation and precise gaps

`contracts.py:105` already types targets and financial basis. `snapshot.py:53,120` already validates as-of daily histories, assignments, coverage and conservation. `models.py:33,82` provides scalar series and predictions. `service.py:128–184` independently invokes scalar predictors per entity; it cannot acquire joint dependence merely by combining their outputs. `uncertainty.py:125` validates and summarizes externally supplied joint paths but fits none. `pricing.py:95` handles full-period synthetic linear/allowance/graduated/volume contracts; `price_paths` returns an expected total but discards per-path allocation detail. These are useful seams, not reasons to replace the existing architecture.

The highest-value changes are: bind every new numerical artifact to its evidence and support; implement a genuine modest joint generator; price and allocate each retained path; expose qualifications independently; run the same delivered procedure on real traces. An actual compact structural generator belongs alongside the aggregate baseline; richer behavioral estimation is optional input detail within these seams. An aggregate-only tenant does not need fictional people, adoption histories or workflow IDs to receive a useful forecast.

## Shared interfaces and state

Retain `Target`, `Snapshot`, `ForecastRequest`, existing source acquisition and financial records. Add a frozen `ScenarioSpec` with `scenario_id`, `kind` (baseline/frozen_usage_repricing/workload/stress), `as_of`, referenced evidence, effective interval, explicitly supplied assumptions, and transform order. Stress weights are not inferred occurrence probabilities. Internal budget changes are never workload transforms.

Add `ProcedureSpec`: method/version, fit cutoff, feature/schema versions, training snapshot IDs, configuration, seed, dependency/model revisions, support regime and output statistic. Fit and calibration manifests are separate immutable references. This prevents a median foundation output, a regression mean and a structural scenario from silently becoming the same numerical object.

Add `ScenarioBundle`: snapshot/target/procedure/scenario references, exact reporting dates/timezone, entity and meter axes, `path_ids`, normalized weights, aligned values, evidence class, support and finite-arithmetic checks. Meter, incurred-money and priced-money bundles are separate typed stages. The minimal aggregate branch can use one target and no meter axis expansion. Each transformation emits a child bundle with parent ID and conservation checks. Never zip independently produced paths because they happen to have matching sample counts.

Add `CapabilityQualification` per requested output: capability, supported status, target digest, exact horizon, entity/population scope, empirical status, evidence artifact IDs, assumptions and reasons. Arithmetic availability differs from empirical calibration. A qualified point can survive unavailable joint risk. An interval qualification does not imply breach probabilities; a conditional bootstrap probability is not a certified safe transfer.

For trace-capable sources, optional immutable execution evidence stores root/logical-operation/physical-attempt IDs, typed causal links, occurred/available times, served configuration, active/terminal state and authoritative meter references. It feeds the same snapshots/bundles. Whole root families can be bootstrapped when observed; wrappers and cumulative summaries remain reconciliation evidence rather than extra charges. No prompt bodies are required. Person exposure and adoption states are only present where supported by supplied roster/execution evidence. Add `ExposureSpell` (eligibility/access, cohort, prior-use known/unknown, effective/available dates), `ConsumedCatalog` (configuration, meter relations, capability evidence and price references) and a small `StateKernel`. Catalog identity is separate from `models.py` forecasting-algorithm registry. Unknown capability remains a bucket, not an invented low score.

## Six cohesive implementation tasks

1. **Contracts and provenance.** Implement the frozen wrappers and validation above, reusing source receipts. Reject incompatible targets, dates, scopes, unknown revisions and mixed evidence classes. Test historical replay and artifact identity. Own new contracts plus narrow serialization changes; no rewrite of the existing daily contracts.
2. **Observation and identity normalization.** Add typed execution/meter ingestion with deduplication, counter epochs and exclusive/subset meter semantics; aggregate genuine observed leaves and preserve unknown coverage. Distinguish accrued prefix, open-root continuation and new roots. This immediately defends retries, fanout and ongoing work without claiming a learned branching model.
3. **One fitted joint generator.** Implement a moving-block empirical residual/bootstrap baseline using complete, as-of mature history and the same sampled block IDs across entities and time. Generate whole aligned panels; support transforms must be declared parts of the evaluated procedure. Store seed, chosen blocks and training window. Residuals come from honest historical forecasts of the same procedure, not in-sample fit errors. Also implement a structural recurrent hurdle generator: fit smoothed state/cohort probabilities of any executed root, then sample a positive count and joint configuration/meter root bag from empirical positive days or explicitly supplied finite tables. Ever-used/recency updates follow emitted qualifying roots; there is no independent first-trial draw. Exposure gates new starts but preserves ongoing roots. Common cohort/day factors or joint bag indices are drawn once per path. Feasible-route tables and shared task-conditioned capability draws support explicit scenarios; absent evidence stays unknown. This is an actual fitted/supplied mechanism, not latent demand inference. Delivered-start mode skips repeat admission; a supplied proposal/control reducer is a separately labeled mode. Retain scalar baselines; cold-start pooled scenarios remain qualified.
4. **Commercial transformation.** For every path, combine required known prefix and explicit late-prefix scenario, price supported complete billing pools once, then allocate exactly with residual buckets. Retain each priced path and its contract/allocation version. Split complete reset periods. Unsupported tax/FX or contractual terms block that monetary view, while native usage and supported components remain available.
5. **Serving and summaries.** Add one joint route to `ForecastService`, executed once per panel. Produce coherent means, quantiles, exceedance and atom-safe tail summaries from exact target path totals; keep conformal intervals and unrelated direct forecasts in separate bundles. Return independent qualifications and immutable provenance. Existing reviewed manual allocation remains possible with unavailable forecasts.
6. **Real benchmark plus adversarial verification.** Run public token traces through strong baselines, the new joint procedure, and at least one genuine pinned pretrained model. Score exact held-out horizons, native usage and explicitly hypothetical monetary transformations. Include failures/abstentions, runtime and sample size. Execute compound fixtures below. A synthetic recovery or pricing test proves mechanics only.

Tasks 1 and the benchmark setup unblock independent workers; task 2 can proceed with task 3; task 4 consumes the settled bundle; task 5 is the integration owner. Do not broaden into a new execution-control product.

## Limits that must not collapse

Delivered usage is neither proposed demand nor telemetry availability. A delivered-count forecast must not pass a second admission filter; first trial must derive from a qualifying executed root if that state exists. A pooled contract is not a sum of standalone customer tariffs. Price-only scenarios do not identify model substitution or rebound. An unreported prefix can change allowance/tier state even with perfect future predictions. Current allocation is authority, not an observed demand ceiling. Calendar intervals and lifetime workflow boundaries are different axes. Marginal intervals, aligned empirical paths and structural counterfactuals are different evidence objects.

The accompanying edge JSON contains twelve compound counterexamples. Agreement among the 20 researchers does not verify the implementation: each defense remains proposed until a fixture or benchmark executes. Collaboration with adoption, data-contracts, workflow, risk and scope workers supports the interfaces; their separate records carry deeper domain detail.
