Its later “it won't ... change the token number” discussion directly agrees with master:17. The settled plan parks swarm management/personal interfaces/provider enforcement (26,228). Therefore “unsupported” cannot be the universal response to demand shifts, incomplete monetary coverage or real benchmark access difficulty.

The forecast object represents a declared quantity/population/time interval. An internal allocation is a finance decision, not observed demand and not a provider limit. Changing the budget must not rewrite the forecast. Capability support and finance authority are separate: a perfectly supported forecast never grants apply authority, and an unavailable forecast does not remove finance's ability to make a manual reviewed decision. ## The decision risk that remains

A selected donor is selected because its estimated surplus looks large. Average forecast accuracy or pooled interval coverage therefore cannot establish safety among selected donors. evaluation.py:323–336 measures retained allocation exposure against matched mature outcomes and correctly labels it noncausal and not safety validation. However it accepts already-selected triples only; there is no replayed selection policy, full candidate denominator, reserve treatment or company-wide adverse event evaluation. A measured policy experiment should select using information available at each historical origin, freeze the withdrawal, then score retained-budget breaches on later mature outcomes. Known obligations and missing obligations must stay separate. Without a supplied business risk limit and useful source coverage, label this descriptive exposure rather than safe-transfer authorization.

There is also no structured proposal impact that makes a reduction below already incurred spending visible. FinanceStore.initialize saves signed recorded_spend but prepare_proposal does not consume it; before/after budgets remain inspectable, so this is not an enforcement violation. A useful improvement is an exact impact summary: donor change, retained allocation, recorded spend, compatible forecast gap, protected reserve and unresolved obligation status. Do not impose an invented prohibition on underfunding already-incurred expense: internal budgets can deliberately expose a shortfall and the plan supplies no universal policy. A host-supplied explicit floor may be enforced through protected_allocations.

“True headroom” is a decision-specific result requiring matched scope and disjoint full-period incurred, future usage and scheduled obligation components, adjusted for an explicit reserve/risk policy. A variable point gap cannot certify it. Unknown obligations are not zero; known fixed commitments must not be estimated again as variable usage. A component forecast remains informative when all-in headroom cannot be identified.

## Top proposed changes

1. Add one reusable proposal-impact result carrying exact current evidence, missing-obligation reasons, retained allocation and explicit no-safety semantics; preserve manual finance review when any forecast capability is unavailable.
2. Extend selected-donor evaluation to replay a named selection/withdrawal policy at each as-of origin, with selected and all-candidate denominators and mature outcome support. No implicit optimality or causal savings.
3. Keep one capability ladder: component forecast, compatible comparison, conditional distribution/risk, policy review; require only the evidence needed for the requested claim. Hard local shifts should trigger adaptation/scenario assessment, not blanket scope exclusion.
4. Tie every proposal's forecasts/context/reserve policy to material dependencies so corrected obligations or plan changes invalidate an unexecuted review. Existing current-dependency comparison is suitable; host completeness remains a documented integration responsibility.
5. Document boundary examples in the unified architecture: internal budget change does not buy tokens; unknown future release excluded, observed adoption change included; proxy token forecast benchmark real, enterprise savings claim unsupported.
