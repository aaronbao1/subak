# Context and structural change

**Proposed design:** ingest enterprise context into a source-backed event ledger and make it available to explanations and explicit scenarios. Decide numerical use through matched-information experiments. Approved intent, observed execution, event timing and magnitude are separate fields. Context quality cannot be assessed solely by persuasive summaries.

**Established evidence:** contextual forecasting benchmarks disagree in meaningful ways. CiK deliberately supplies essential context; TimesX evaluates a different public-event setting and finds tested revision mechanisms can underperform simpler combinations; GIFT-Eval-CTX uses effects derived from realized future values to test effect-to-trajectory translation. These are distinct tasks, not an escalating proof of enterprise forecasting accuracy. Exact primary versions, results and limits appear in [context research](tracks/13-context.md).

**Inference:** a diagnostic that gives a model true future effects can test whether it uses information, but cannot establish that Factory can discover those effects before the outcome. **Unvalidated hypotheses:** internal plans contain useful advance signal; human-verified structure is sufficient to capture it; Factory preserves that value after retrieval/extraction delay and error.

## Event ledger

Record canonical initiative/event ID, revision and source versions/hash/offsets; affected entities; event category; author/authority where known; publication, first-available, ingestion, extraction and review times; proposed/approved/scheduled/executing/completed/delayed/cancelled/disputed state; applicable date or range; supersession/duplicate/contradiction links; quantities with source units; and numerical eligibility with reasons.

Several messages repeating one initiative do not establish several spending increases. A newer informal message does not automatically overrule an approved plan. Keep conflicts visible and inactive for automatic numerical adjustment until a justified resolution exists. A later cancellation cannot enter an earlier origin. Source metadata gaps remain unknown; they are not backdated to project start.

Feature availability is the maximum relevant processing/ingestion/review time, not just the event date. An idealized retrospective extraction from archived text differs from an operational replay with actual extraction completion. Current permissions also govern present retrieval; historical access does not authorize disclosure now. Treat source text as evidence, not commands to alter accounting or apply allocations.

## Controlled comparison

Use the same numeric target, cutoffs, calendar/commercial information, search budget and evaluation periods across: history-only; human-verified as-of events; Factory events with the same schema/mapping; text embeddings; direct LLM forecast; numeric/LLM mixture or revision; and unchanged numerical forecasts with context explanations/scenarios only. Human verification is a diagnostic for extraction quality, not an oracle of realized future effects.

Run no-context and irrelevant/duplicated/contradictory-context controls. Freeze encoder/prompt/tool versions; count failed outputs, fallback, review effort and API cost. Train context coefficients on preceding observations only. Direct LLM repeated samples are not automatically a calibrated predictive distribution. Test execution timing/cancellation separately from event extraction.

Northstar acceptance preserves one current research initiative with its superseded earlier correspondence; the delayed product launch does not set all product usage to zero; continuing engineering work need not imply an uplift. The supplied projections remain synthetic and must not be described as calculated from these events unless a real model does so.

## Structural change diagnosis

Distinguish workload volume, task/model mix, token intensity, cache/retries, unit prices/contracts, organizational mapping and observed source coverage. A billing rerating, newly included account or instrumentation change can resemble adoption. Investigate collection and target continuity before changing a behavioral model.

Compare recent and long windows, discounting, adaptive levels, explicit interventions, regime switching and guarded expert combinations. Change detection, cause identification and forecast adaptation are different stages. The [structural-change track](tracks/14-change.md) documents why BOCPD/ADWIN/CUSUM assumptions and guarantees do not imply instant or fleet-wide reliable adaptation. Retain a replayable old model; do not delete history on one spike.

Separate access eligibility, activation and intensity. Adoption can be abrupt, delayed, gradual or reversed. A cheaper model can increase usage, and a task migration can overlap old/new tools. No universal adoption curve or two-week recovery guarantee is supported. Unannounced releases belong to stress scenarios, not fabricated probabilities.

## Uncertainty and release gates

Shared initiatives need shared path states across affected teams, while residual dependence is separately modeled. If execution/magnitude probabilities are unsupported, present conditional scenarios without probability labels. Price-only scenarios hold demand fixed explicitly. A full-period risk output must include supported late-incurred and future components jointly, not independently add their upper bounds.

First test whether human-verified as-of context improves the decision target. If it does not, distinguish absent relationship, incomplete labels and insufficient evidence rather than blame extraction. If it succeeds but Factory fails, improve retrieval/extraction/review. Embeddings, LLM revisions or learned ensembles need gains over the strongest simpler eligible comparator. Explanation-only context may still improve comprehension and auditability in a separate workflow study. No predictive or causal savings claim follows from that study alone.
